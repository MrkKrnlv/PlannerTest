# Планер

Личный планер, который живёт в браузере, ставится на телефон как приложение, открывается как Telegram Mini App и синхронизируется между всеми устройствами. Задачи можно надиктовать боту голосом: он расшифрует, разложит по дням с учётом загрузки и добавит в планер. Задачи с датой уходят в Notion Calendar.

Всё живёт в одном Cloudflare-проекте: Worker со статикой, база D1, Workers AI для голоса и разбора, cron для синка с Notion. Работает в рамках бесплатного тарифа.

## Что умеет

Навигация: **Сегодня**, **Планы**, **«+»**, **Рост**, **Ещё**. Всё новое добавляется через «+»: задача, привычка, заметка, таймер.

**Сегодня**
- Карточка «Сейчас»: текущая задача, ближайшая или что взять в свободное окно, с кнопками «Фокус» и «Готово».
- Блоки задач по времени: высота зависит от длительности, видны свободные окна и линия «сейчас». Ниже задачи без времени, хвосты с прошлых дней, привычки на день.
- **Спланировать день**: шкалы «Время» и «Голова», что перенести на завтра при перегрузе, предпросмотр автоплана. Главное и глубокая работа уходят в пик энергии, мелочи после него, обед свободен, расстановку можно отменить.
- **Завершить день**: три шага. Разобрать несделанное (сделано, завтра, во входящие, удалить), отметить настроение и энергию, записать, что было хорошего.
- Быстрый ввод: `созвон с клиентом 1.5ч в 16:00 завтра #работа !`. Понимает `завтра`, дни недели, `утром/днём/вечером`, `!` (важно), `!!` (главное на день), `~` (не срочно).
- Поиск по задачам и заметкам (`Ctrl+K`).

**Задачи**
- Повторы: каждый день, по будням, по дням недели, каждый месяц. Следующая появляется, когда отмечаешь текущую.
- Подзадачи-чеклист.
- Главное на день, глубокая работа, сфера, приоритет, заметка, фокус-таймер прямо из задачи.

**Планы**
- **Входящие**: задачи без даты, разбор в один тап (сегодня, завтра, дата).
- **Неделя**: баланс по сферам и метка «лёгкий день».
- **Месяц**: загрузка, очки (10, 25, 30 за задачу по размеру, 40 за главную на день), серия дней подряд, рекорды по дням недели.

**Рост**
- Привычки: дни недели, серии, процент за месяц, сетка за 14 дней, напоминания.
- Сферы жизни: недельная цель в часах, прогресс, тихие подсказки про забытые сферы.
- Цикл 12 недель: цели, еженедельные шаги, процент по неделям против 85%.

**Ещё**
- Таймеры: фокус 25/50 и параллельные побочные таймеры, переживают перезагрузку.
- Заметки с поиском (`Ctrl+J`).
- **Экспорт месяца для Claude**: кнопка копирует готовый запрос на разбор и все данные месяца одним блоком, можно скачать JSON.
- Настройки дня: рабочие часы, пик энергии, обед, нормы.
- **Импорт** задач, привычек и сфер одним JSON; повторный импорт ничего не задваивает.
- Тема: как в системе или Telegram, светлая, тёмная (кнопка в «Ещё» и в настройках).
- Знакомство с разделами (показывается при первом входе).

**Везде**
- Синхронизация между устройствами, работа без сети, PWA.
- Telegram Mini App с входом без пароля, темой и хаптиками.
- Дизайн liquid glass: матовые панели поверх мягкого фона. Blur только на навигации, шапках и шторках, строки списков без него, чтобы не тормозило в слабых WebView.

## Архитектура

```
 Браузер / PWA / Mini App                 Cloudflare (один Worker)                     Снаружи
 ┌──────────────────────┐   Bearer   ┌──────────────────────────────┐   вебхук   ┌──────────────┐
 │ React + Zustand      │──────────▶│ /api + статика               │◀──────────│ Telegram-бот │
 │ localStorage (копия) │◀──────────│ D1 · Workers AI · cron 5 мин │──────────▶│ Notion       │
 └──────────────────────┘  дельта    └──────────────────────────────┘  задачи    └──────────────┘
```

| Слой | Что |
|---|---|
| Фронт | React 19, Zustand 5 (persist в localStorage), Vite 8, чистый CSS, шрифт Golos Text (self-hosted) |
| API | Cloudflare Worker: `server/worker.js` отдаёт `/api/*`, остальное — статика из `dist/` |
| Бот | `server/bot.js`: вебхук Telegram, Whisper Large V3 Turbo и Llama 3.3 70B на Workers AI |
| Notion | `server/notion.js`: cron раз в 5 минут досылает изменения задач в базу Notion |
| База | Cloudflare D1. Схема создаётся сама при первом запросе (`server/schema.js`) |
| Офлайн | `public/sw.js`, `public/manifest.webmanifest` |

### Данные

| Таблица | Что хранит |
|---|---|
| `tasks` | задачи построчно, включая повтор и подзадачи (их же пишет бот) |
| `items` | документы `kind + JSON`: привычки и отметки, итоги дней, сферы, цикл 12 недель, цели и шаги, настройки дня |
| `users` | пользователь Telegram, его ключ и настройки Notion |
| `notion_pages` | какая страница Notion соответствует задаче |

Таймеры живут только на устройстве.

### Как устроен синк

Одинаково для задач и документов:

1. Каждая правка поднимает у записи `updated_at` и помечает её грязной.
2. **Push:** грязные записи уходят целиком (`POST /api/tasks/sync`, `POST /api/items/sync`). Сервер применяет правку, только если она новее сохранённой (last-write-wins по записи).
3. **Pull:** клиент забирает всё, что изменилось после его ревизии (`GET …?since=<rev>`). `rev` — серверный счётчик, а не время клиента, поэтому неточные часы на телефоне ничего не ломают.
4. Удаление — это надгробие `deleted = 1`, оно синкается как обычная правка, и запись не «воскресает».
5. Отметки привычек и шагов имеют детерминированные id (`hl:<привычка>:<дата>`), поэтому отметки с двух устройств сливаются, а не дублируются.

Почему D1, а не KV: KV eventually consistent (запись расходится до минуты) и на бесплатном тарифе даёт 1000 записей в сутки. D1 — это SQLite с транзакциями, плюс бот может добавлять отдельные задачи, не трогая остальные.

### Авторизация

| Кто | Как |
|---|---|
| Mini App | `initData` от Telegram → `POST /api/auth/telegram` проверяет подпись токеном бота и выдаёт персональный ключ |
| Браузер / PWA | Тот же ключ: Mini App → Ещё → Настройки → «Ключ для браузера» |
| Telegram-бот | вебхук с секретом, выведенным из токена бота; пользователь определяется по Telegram id |
| Внешние автоматизации (n8n, Make) | `X-Service-Key` + `X-Telegram-User-Id`: `POST /api/tasks`, `GET /api/tasks?from&to` |

## Локальный запуск

```bash
npm install
cp .dev.vars.example .dev.vars
npm run build
npm run dev:api      # Worker: API и собранный фронт на http://localhost:8788
npm run dev          # во втором терминале: фронт с автообновлением на http://localhost:5173
```

На экране входа введи `dev`.

Проверки:
- `npm run test:api` — синк, LWW, удаления, документы, доступ по service key, изоляция пользователей;
- `npm run test:logic` — автоплан, нагрузка, привычки, 12 недель, очки, повторы, экспорт, разбор ввода;
- `npm run test:integration` — бот (голос, текст, запасной разбор) и синк с Notion на настоящей SQLite с подменёнными Telegram, Workers AI и Notion API.

Локально Workers AI недоступен без токена Cloudflare, поэтому `dev:api` использует `wrangler.local.toml` без AI. Бот проверяется интеграционным тестом.

## Деплой

Через дашборд Cloudflare:

1. **База.** Storage & databases → D1 → Create, имя `planner`. Её id вписать в `wrangler.toml` → `database_id`. Таблицы создадутся сами.
2. **Worker.** Workers & Pages → Create → Import a repository → этот репо. Build command `npm run build`, Deploy command `npx wrangler deploy`. Имя Worker должно совпадать с `name` в `wrangler.toml`.
3. **Секреты.** Settings → Variables and Secrets → Add, тип **Secret**: `BOT_TOKEN` и, если нужен доступ внешним автоматизациям, `SERVICE_KEY`. Именно Secret: обычные переменные, которых нет в `wrangler.toml`, стираются при следующем деплое из Git.
4. Привязки Workers AI (`AI`) и cron подтягиваются из `wrangler.toml` сами.
5. Каждый пуш в `main` деплоится сам.

Или из консоли:

```bash
npx wrangler login
npx wrangler d1 create planner          # id -> wrangler.toml
npx wrangler secret put BOT_TOKEN
npx wrangler secret put SERVICE_KEY     # openssl rand -hex 32
npm run deploy
```

## Бот и Mini App

1. `@BotFather` → `/newbot` → получишь токен (его же в `BOT_TOKEN`).
2. `/mybots` → бот → Bot Settings → Mini Apps → Menu Button → URL приложения с `https://`, текст «Планер».
3. Открой бота, нажми «Планер». Вход произойдёт сам.

## Голосовой бот

Бот живёт в том же Worker. После деплоя открой планер → Ещё → Настройки → «Подключить бота к планеру». Кнопка сделает три вещи:
- поставит вебхук бота на Worker;
- включит кнопку «Планер» в меню бота;
- добавит команду /start.

Если раньше бот был подключён к n8n, вебхук переключится на Worker.

Как это работает:
1. Голосовое скачивается из Telegram и расшифровывается Whisper Large V3 Turbo на Workers AI.
2. Llama 3.3 70B в JSON-режиме разбирает текст в задачи. Модель видит уже запланированное на неделю, поэтому не ставит задачи на занятое время, оценивает длительность, помечает глубокую работу и главное на день, дробит размытые задачи.
3. Задачи пишутся в D1, бот отвечает списком и кнопкой «Открыть планер».

Если модель не выдержала схему, срабатывает запасной разбор обычного ответа. Логика и промпт лежат в `server/bot.js`, часовой пояс — `Europe/Moscow`.

Расход виден в дашборде Cloudflare → AI. На личное использование бесплатной суточной квоты должно хватать.

## Notion Calendar

У Notion Calendar нет API, но он показывает базы данных Notion. Поэтому планер пишет задачи с датой в базу «Планер»:

1. На notion.so/profile/integrations создай внутреннюю интеграцию и скопируй секрет.
2. Создай пустую страницу «Планер», нажми «•••» → Connections и добавь интеграцию.
3. В планере открой Ещё → Настройки → Notion Calendar, вставь секрет и ссылку на страницу. Внутри страницы появится база со свойствами: Задача, Когда, Готово, Сфера, Минут, Главное.
4. В Notion Calendar включи эту базу в списке календарей.

Синк односторонний (планер → Notion): новые задачи, правки, отметки «готово» и удаления уходят раз в 5 минут или по кнопке «Синхронизировать сейчас». Задачи без даты не уходят. Токен интеграции хранится в D1 и на устройства не попадает.

## Ограничения

- LWW работает по записи целиком: если одну задачу одновременно правят на двух устройствах, победит более поздняя правка.
- Надгробия удалённых записей не чистятся. Для личного планера это килобайты.
- Ключ браузера бессрочный, ротации пока нет.
- Напоминания привычек срабатывают, пока планер открыт. Внутри Telegram системных уведомлений нет.
- Синк с Notion односторонний; правки, сделанные в Notion, в планер не возвращаются.
- За один запуск cron отправляет до 35 изменений (лимит внешних запросов на бесплатном тарифе), остальное уходит следующими запусками.
- Из РФ `*.workers.dev` у части провайдеров открывается медленно или нестабильно. Проверь до публикации видео. При проблемах привяжи свой домен.

## Структура

```
server/worker.js      точка входа Worker, роутинг /api
server/routes/        обработчики API (middleware.js — авторизация и схема)
server/bot.js         голосовой бот: Telegram + Workers AI
server/notion.js      синк задач в Notion
server/               схема, задачи, документы, crypto, users
src/store.js          состояние и действия
src/lib/              синк, автоплан, нагрузка, повторы, привычки, 12 недель, очки, сферы, экспорт, разбор ввода, Telegram
src/components/today/ экран «Сегодня»
src/components/day/   лента недели, план дня, привычки на день
src/components/sheets/ шторки: добавить, спланировать, завершить день, поиск
src/components/       планы, рост, таймеры, заметки, экспорт, настройки, онбординг
public/               manifest, service worker, иконки
scripts/              тесты API, логики и интеграционный, генерация иконок
```
